## 단계

### 1단계 — 계정 만들기 + 이름 연결 (서버)
- 계정 생성은 **사용자가** Supabase 대시보드 → Authentication → Add user → *Send invitation*(학교 메일). 비밀번호는 각 선생님이 직접 정함.
- `sql/60_admin_display_name.sql`(멱등): `admin_users.display_name text` 추가, `current_admin_name()`(로그인한 관리자의 이름) 함수. 권순천·김성훈 값 채움, 새 3명은 초대 뒤 행 추가.
- **확인:** 각 계정으로 로그인하면 머리에 이름이 보이고, mju 데이터만 보임(mju-ksh 0건).

### 2단계 — '지금 보는 범위' 띠 + 내 학생 기본값
- 오늘·학생·보내기 화면 위에 띠: **"차민정 담당 n명 · [전체 보기]"**. 선택은 이 기기에 기억.
- 학생 표 '담당직원' 필터 기본값 = 나. 명단 등록·추가에서 담당직원 기본값 = 나.
- 담당 학생이 0명이면 띠에 "명단 등록·추가에서 내 학생을 넣어주세요" 안내.

### 3단계 — 출결 원본을 앱으로, 노션 빼기
> **10/16 구현(sql/61 + admin·index, 운영 적용 전):** 사용자 "노션은 아예 지우자" → mju-ksh 까지 노션 크론·RPC 삭제(김성훈 선생님 진도는 엑셀/숫자 입력으로 옮겨야 함 — 미리 알림). 2026 기수 OFF-JT 는 100% 이수로 간주해 2026-07 한 행(1유형 192h·2유형 60h, mju만). 누적·전체 출석률은 끝난 달까지만. 엑셀 읽기는 브라우저(SheetJS 0.18.5, cdnjs)에서 — 9월 TPC 저장본으로 파이썬 파서와 같은 결과(3명×11일·60h) 확인.
- **서버(sql/61):** `attendance_monthly`에 `source`(excel·manual)·`edited_by`·`edited_at` 추가. 엑셀로 올리면 그 달 실적 = 날짜별 인정 합계로 다시 계산. **손으로 고친 값(manual)은 다음 올리기에도 덮어쓰지 않음**("수정됨" 표시, [엑셀 값으로 되돌리기]).
- **입력 길 ① 출석결과 엑셀 올리기:** 콘솔에 엑셀 여러 개를 끌어놓기 → 브라우저에서 읽기(파일은 서버에 저장하지 않음) → 이름으로 명단 매칭·미리보기 → 올리기. 권순천 자동 조회도 같은 엑셀을 저장해 두므로 이 길로 같이 씀(앱용 JSON 단계 제거).
- **입력 길 ② 숫자 입력:** 학생 표/상세에서 그 달 실적·예정·메모 직접 입력. 엑셀 없이 쓰는 선생님용이자 모두의 보정 수단(노션 '비고' 대체).
- **월 예정 시수:** 과정별 월 1회 입력(첫 값 = 엑셀의 정규 등록 합계). 시간표 배정과 다를 수 있어서(예: 프라임 10월 등록 90h · 시간표 72h). 10월 값은 지금 노션 '예정 시수'를 한 번 옮겨 와서 시작.
- **노션 빼기:**
  - 콘솔의 [노션 출석진도 반영] 버튼·"노션 실적" 문구 삭제, 진도 숫자는 앱 값만.
  - 노션 자동 동기화 크론(`notion-sync-daily`, 평일 08:45, mju·mju-ksh 둘 다 돎) 끄기 — **mju는 이 단계에서 바로, mju-ksh는 김성훈 선생님이 엑셀/숫자 입력으로 옮긴 뒤**(그 전에 끄면 그쪽 진도가 멈춤, 미리 알려야 함).
  - `sync-attendance` 함수·NOTION_TOKEN은 두 센터 모두 끈 뒤 삭제.
  - ojt-attendance 스킬: '노션 갱신' 단계 삭제, "100% 과정 조회 생략" 판단을 앱 DB에서 읽기로.
- **주의:** 평일 09:00 비콘 알림 본문의 시수가 `attendance_monthly`를 읽음 → 노션 크론이 없으면 **마지막으로 올린 값**이 나감. 아침 알림을 정확히 하려면 조회·올리기를 전날이나 9시 전에.
- **확인:** 권순천 10월 엑셀 올린 뒤 진도 숫자 = 노션 최신 실적(다르면 원인 표), 손 수정값이 재업로드에 살아남음, 크론 끈 다음 날 08:45에 attendance_monthly가 바뀌지 않음.

### 3-1단계 — 출석 진도를 OFF-JT / OJT 따로 (사용자 10/16: "출석 진도(시수)·학생 앱 화면에 OFF-JT랑 OJT 칸을 따로")
- **현황(10/16):** `attendance_monthly`·`attendance_daily`에 구분 칸이 없음 — 지금 데이터는 8월~2월 OJT뿐(월별 17명, 예정은 노션에서 옴). 학생 홈 카드 제목이 "M월 OJT 출석"으로 고정, 누적은 실적 있는 달만 합침. 출석결과 엑셀에는 날짜마다 **OJT 시작/종료·Off-JT 시작/종료 칸이 따로** 있음.
- **서버(3단계 sql/61에 함께):** 두 표에 `track`('offjt'|'ojt', 기존 행 = 'ojt') 추가, 유일 키를 (센터·이름·월/날짜·track)으로. 엑셀 올리기는 날짜마다 OJT 칸·Off-JT 칸을 따로 읽어 각 track 행으로, 숫자 입력은 track을 골라 입력. 학생별 **전체 훈련시간**(OFF-JT 총시간 + OJT 총시간, 실시신고 기준)을 두는 칸 — 80% 판정 분모.
- **관리자 학생 › 출석 진도 표:** 이름 | **OFF-JT** 실적/예정(누적) | **OJT** 이번 달 실적/예정 · 누적 | **전체 출석률**(80% 밑으로 갈 것 같으면 표시). 3유형처럼 둘을 같이 하는 학생은 두 칸 모두.
- **학생 앱 홈 카드 '내 출석 진도':** 두 줄 — "OFF-JT 152 / 192h(79%)" · "OJT 10월 30 / 40h · 누적 …" + 맨 아래 "전체 출석률 n% — 외부평가 응시 기준 80%". 지금 단계(sql/59)에 맞는 줄을 위로, 아직 시작 전인 쪽은 숨김. 제목의 "OJT" 고정 문구 제거. 학생 페이지가 바뀌므로 `sw.js` CACHE 올림.
- **비콘 알림:** 본문 시수는 OJT track만 읽게(지금과 같은 숫자).
- **확인:** 기존 OJT 행이 'ojt'로 그대로 보임(학생 카드 숫자 변화 없음), 2026 기수 OFF-JT 칸은 데이터가 없으면 '–'로, 엑셀 1개를 올려 OJT·Off-JT 칸이 각각 맞게 들어가는지.

### 4단계 — 오늘 화면을 내 몫으로
- 처리할 일 · 알림 못 받는 학생 · 이번 달 마감 미완료 · 모자란 학생을 **보는 범위 기준**으로 집계.
- 상담: 학생 이름 → 명단 담당직원으로 '내 학생 상담'을 먼저, 나머지는 접어서.
- 출결 카드에 "내 학생 마지막 반영: 10/16 엑셀 · 3명 미반영".

### 5단계 — 보내기
- 받는 대상 기본값 = **내 학생 전체**(`custom.managers=[나]`). '가입자 모두'를 고르면 "다른 선생님 학생 n명에게도 갑니다" 확인.
- 발송한 공지·발송 기록에 **보낸 사람** 표시, [내가 보낸 것만] 기본.

### 6단계 — 공용 화면 표기 정리
- 최근 활동·자료·FAQ·일정에 올린 사람 이름.
- 자료 대상의 `custom:{...}` 원문을 "학생 · 담당 권순천"처럼 읽는 말로.
- 설정 하위 탭 이름 옆에 "센터 공용" 표시.
