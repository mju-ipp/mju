> **진행:** 1단계 ✅ 배포(f561460) · 2단계 ✅ 배포(메뉴 5개 + 하위 탭, 1단계 좁은 화면 회귀 수정 포함) · 3단계~ 대기

> 기준 시안: `04_일학습병행앱_v2/design/관리자_시안.html`, 토큰: `04_일학습병행앱_v2/DESIGN.md`.

## 현황 (실측)
- `admin.html` 3,415줄 단일 파일. 탭 = `TAB_KEYS` + `showTab()` + `location.hash`. 메뉴 9개, 숨긴 섹션 3개(stages·centers·vote).
- 스타일은 학생 앱과 같은 `styles.css`를 공유 → **관리자 전용 덮어쓰기는 `body.adm` 범위로만** 해야 학생 화면이 안 바뀐다.
- 출석 데이터는 월 단위뿐: `attendance_monthly`(이름·월·예정·실적, sql/42) ← 노션 동기화(`sync-attendance`, sql/53 크론).
- **날짜별 정규시간·인정시간은 서버에 없다.** 원천은 출결점검의 `data/beacon_YYYY-MM.json` — 과정별 `plan{날짜:[시작,종료,시간]}` + 학생(연번)별 `hours{날짜:인정}`·입퇴실·방식. **이름이 없고 연번만** 있다.
- 푸시 수신 상태는 `admin_push_status()`(sql/46)로 이미 조회 가능.

## 목표 화면 (시안과 같음)
메뉴 5개 — **오늘 · 학생 · 보내기 · 상담 · 설정**. 기존 해시(#notice, #members, #attn …)는 새 메뉴로 넘겨 북마크가 깨지지 않게 한다.

| 새 메뉴 | 들어가는 기존 섹션 |
|---|---|
| 오늘 | sec-dash 새로 작성 (정규시간 모자란 학생 · 미답변 상담 · 푸시 미수신 · 이번 달 마감 · 0건 항목 접기) |
| 학생 | sec-members + sec-attn + sec-onboard 합침. 행 클릭 → 학생 상세(10월 정규시간 달력) |
| 보내기 | sec-notice + 발송 기록. 자료·일정·설문 첨부, 같은 제목 10분 내 재발송 경고 |
| 상담 | sec-consult (스타일만) |
| 설정 | sec-library · sec-calendar · sec-recruit(FAQ) · sec-survey 하위 탭 |

## 단계

### 1단계 — 디자인 입히기 (기능 변경 없음)
- `admin.css` 신설: DESIGN.md 토큰(먹색·코발트 하나·warn, Noto Sans KR, 크기 8단계), `body.adm` 범위로 머리·메뉴·카드→선·버튼 3종(주/선/글자)·표·칩 덮어쓰기.
- 기본 브라우저 버튼(이름 복사·안내 공지 초안)에 클래스 부여, 이모지 아이콘 정리, '0'에 경고색 쓰지 않기, 가입자 표 내부 스크롤 제거(머리글 고정).
- **확인:** 9개 탭 전부 로그인 상태로 열어 캡처, 학생 앱 `index.html`·`calendar.html` 변화 없음.

### 2단계 — 메뉴 5개로 재배치
- nav·`TAB_KEYS`·`showTab()` 재구성, 옛 해시 → 새 메뉴 매핑. 섹션 DOM은 옮기기만 하고 로직은 그대로.
- **확인:** 옛 해시 10개 모두 올바른 화면으로 열림, 각 화면 기능(공지 발행 제외 — 실발송) 동작.

### 3단계 — 날짜별 정규시간 데이터 (서버)
- `sql/55_attendance_daily.sql`(멱등): `attendance_daily(center_id, name, day, start_time, end_time, planned_hours, recognized_hours, method, status, fetched_at)`, unique(center_id,name,day). RLS = attendance_monthly와 같은 관리자 센터 스코프. **anon 정책 없음.**
- RPC `bulk_upsert_attendance_daily(p_rows jsonb, p_month date)` — 관리자만, 올린 학생의 그 달 행을 통째로 교체(정규시간을 옮기면 옛 날짜가 지워지게).
- RPC `my_attendance_days(p_code, p_token)` — `my_attendance`와 같은 본인 확인, **이번 달 행만** 반환.
- `rls-check.html` MUST_BE_BLOCKED에 `attendance_daily` 추가, 점검 통과.
- **운영 DB 적용은 사용자 확인 후.**

### 4단계 — 출결 결과 올리기 (PC → 앱)
- 출결점검 `scripts/app_export.py <yyyy-MM>`: beacon JSON + **연번↔이름 대응표 `app_map.json`(로컬 전용, 처음 한 번 작성)** → `reports/app_upload_<yyyy-MM>.json`.
- 상태 판정: 조회 범위 안 정규시간 날 — 인정 ≥ 정규 → `인정`, 0 < 인정 < 정규 → `모자람`, 0 → `기록 없음`. 범위 밖 = 예정.
- 관리자 '오늘' 화면에 **[출결 결과 올리기]** — 파일 고르기 → 학생 수·날짜 수 미리보기 → 업로드. 비밀키를 PC에 두지 않기 위해 관리자 로그인 세션으로 올린다.
- ojt-attendance 스킬 루틴 끝에 "앱용 파일 만들기"를 추가.

### 5단계 — 오늘·학생 화면을 정규시간 기준으로
- 오늘: "정규시간보다 인정시간이 모자라요"(오늘까지 정규 대비) + 모자란 날짜·사유, 조회 시각.
- 학생 표: 이름·기업·직무·인정/오늘까지 정규·월 계획·상태(점+글자)·알림, 모자람 먼저 정렬. 행 → 상세(달력·받은 공지·기기).
- 확인 업무: 독촉 버튼은 마감 D-3부터.
- 진도 탭의 달력 비율('월 경과 %') 판정 제거.

### 6단계 — 학생 앱 달력
- `calendar.html`: `my_attendance_days` 결과로 훈련 날(코발트 바탕+시간)·지난 날 상태 표시, 머리에 조회 시각. 다른 달로 넘기면 센터 일정만.
- `index.html` 출석 진도 카드에 "다음 훈련 10/16(금) 09:00–16:00".
- 데이터가 없는 학생(다른 담당자)은 지금과 똑같이 보임.

### 7단계 — 보내기 통합
- 공지 작성에 자료·일정·설문 첨부. 자료·일정·설문 화면의 "공지로도 알림" 체크 제거(첨부로 대체).
- 발행 전 같은 제목이 10분 안에 나갔으면 경고. 발송 기록에 도착·읽음·못 받은 사람 이름 복사.
